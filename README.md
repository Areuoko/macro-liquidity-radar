# Macro Liquidity & Central Bank Radar

رادار هفتگی نقدینگی کلان و بانک‌های مرکزی — یک موتور Python که هر دوشنبه صبح (UTC) اجرا می‌شود، داده‌های کلان را از FRED، Yahoo Finance، DeFiLlama و CFTC جمع می‌کند، دو امتیاز مستقل (استرس سیستمی و چرخش بازار) محاسبه می‌کند و گزارش فارسی HTML را به تلگرام و Discord ارسال می‌کند.

اجرای خودکار با GitHub Actions انجام می‌شود؛ اجرای دستی هم با `workflow_dispatch` یا به‌صورت محلی ممکن است.

## معماری کلی

```
FRED API ──┐
Yahoo Finance ──┤
DeFiLlama ──┼──> macro_alpha_engine.py ──> stress_score + rotation_score ──> گزارش فارسی ──> Telegram / Discord
CFTC (Socrata) ──┤
Gemini (اختیاری) ──┘
```

- `macro_alpha_engine.py` — کل موتور (fetch، کش، محاسبات، امتیازدهی، گزارش، ارسال). تاریخچه کامل تصمیم‌های طراحی در docstring ابتدای همین فایل.
- `run_once.py` — نقطه ورود اجرا.
- `data_cache.json` — کش بین‌اجراها (با قدم commit-back در ورک‌فلو بین اجراها persist می‌شود).
- `.github/workflows/macro_radar.yml` — زمان‌بندی و دیپلوی.

## فلسفه کیفیت داده

هیچ عدد جعلی به‌عنوان «داده زنده» نمایش داده نمی‌شود. هر متریک یکی از سه وضعیت را دارد:

| وضعیت | معنی | نمایش در گزارش |
|---|---|---|
| `live` | همین اجرا از منبع اصلی خوانده شد | بدون برچسب |
| `cached` | منبع اصلی شکست خورد؛ آخرین مقدار موفق قبلی | `(کش <تاریخ>)` |
| `missing` | نه داده زنده و نه کش موجود | `N/A ⚠️` |

همچنین هر سری قبل از استفاده بررسی تازگی می‌شود؛ آستانه‌ها per-frequency هستند چون یک آستانه سراسری برای فرکانس‌های مختلف data gap کاذب می‌سازد:

| سری | آستانه تازگی | دلیل |
|---|---|---|
| سری‌های روزانه (T10Y2Y، OAS، SOFR، ...) | ۴ روز | پیش‌فرض روزانه |
| WALCL / ECBASSETSW | ۱۰ روز | انتشار هفتگی |
| JPNASSETS (BoJ) | ۷۵ روز | ماهانه، تأخیر انتشار ~۶۳ روز |
| TRESEGCNM052N (ذخایر ارزی چین) | ۱۲۰ روز | ماهانه، تأخیر انتشار ~۹۳ روز |
| CFTC COT | ۱۰ روز | هفته‌ای یک‌بار، با تعطیلات |

متریک‌های غیر-live همه در پاورقی «هشدار کیفیت داده» گزارش لیست می‌شوند.

## متریک‌های گزارش

**۱. نقدینگی و بانک‌های مرکزی** — نقدینگی خالص فدرال‌رزرو (WALCL − TGA − RRP، تغییر ۳۰ روزه)، شیب منحنی ۱۰-۲ ساله، HY/IG OAS، اسپرد SOFR-EFFR، رشد ترازنامه ECB/BoJ، ذخایر ارزی چین (پراکسی PBoC — چون FRED ترازنامه کامل PBoC ندارد)، رشد استیبل‌کوین‌ها (DeFiLlama).

**۲. بازدهی هفتگی دارایی‌ها** — S&P 500، طلا، نفت، BTC، DXY (هر نماد جداگانه fetch می‌شود تا تقویم‌های ۵روزه و ۷روزه قاطی نشوند).

**۳. سیگنال‌های چرخش (Rotation)** — سه نسبت ETF: Growth/Value (IWF÷IWD)، Cyclical/Defensive (XLY÷XLP)، Small/Large (IWM÷SPY)؛ سطح فعلی + مومنتوم ۵روزه.

**۴. پول هوشمند (CFTC COT)** — خالص پوزیشن Leveraged Funds در S&P 500 Consolidated و USD Index؛ تغییر هفتگی به‌صورت خامِ کانترکت (نه درصد، چون خالص پوزیشن می‌تواند از مثبت به منفی رد شود).

**۵. ارزیابی ریسک** — دو امتیاز مستقل:

- `stress_score` (۰ تا ۱۰۰): ۴ ورودی حیاتی (شیب منحنی ۲۰، HY OAS ۲۵، VIX ۲۰، نقدینگی فد ۱۰) + ۳ ورودی اختیاری (IG OAS ۱۰، SOFR-EFFR ۱۰، تغییر هفتگی COT سهام ۵). غیبت یک ورودی حیاتی کل امتیاز را N/A می‌کند؛ غیبت ورودی اختیاری فقط سهم خودش را صفر می‌کند. خروجی: شاخص + برچسب فاز بازار.
- `rotation_score`: میانگین ساده مومنتوم ۵روزه سه نسبت فاز ۳ (هم‌مقیاس، بدون وزن‌دهی). ±۱.۵٪ آستانه برچسب چرخش واضح.

**۶. تفسیر تحلیلی (اختیاری، Gemini)** — نسخه بدون-تگ بخش‌های ۱ تا ۵ به Gemini داده می‌شود تا رابطه/تناقض متریک‌ها را به فارسی توضیح دهد. کاملاً اختیاری: بدون کلید یا در صورت خطا فقط همین بخش حذف می‌شود. systemInstruction تحمیل می‌کند که تفسیر با برچسب‌های رسمی محاسبه‌شده هم‌خوان باشد و صرفاً «تفسیر» باشد، نه توصیه مالی.

## مدل‌های Gemini

به‌جای پین‌کردن نسخه ثابت، زنجیره‌ی candidates استفاده می‌شود:

1. `gemini-flash-latest` — alias رسمی گوگل، با هر ریلیز خودکار عوض می‌شود
2. `gemini-flash-lite-latest` — alias سبک‌تر backup
3. `gemini-3.1-flash-lite` — نسخه pin‌شده، آخرین خط دفاعی

خطای 404 روی یک مدل فوراً به مدل بعدی می‌رود (retry بی‌فایده است)؛ خطاهای دیگر دو بار روی همان مدل retry می‌شوند.

## راه‌اندازی

### Secrets لازم (GitHub → Settings → Secrets and variables → Actions)

| Secret | الزامی | کاربرد |
|---|---|---|
| `FRED_API_KEY` | ✅ | API رسمی FRED (رایگان: [fred.stlouisfed.org](https://fred.stlouisfed.org/docs/api/api_key.html)) |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` | یکی از دو کانال | ارسال گزارش به تلگرام |
| `DISCORD_WEBHOOK_URL` | اختیاری | ارسال به Discord |
| `GOOGLE_AI_STUDIO_API_KEY` | اختیاری | فعال‌سازی بخش «۶. تفسیر تحلیلی» |

### اجرای محلی

```bash
pip install -r requirements.txt
# متغیرهای محیطی را در .env یا shell تنظیم کنید
python run_once.py
```

### زمان‌بندی

دوشنبه‌ها ساعت ۰۶:۰۰ UTC (قبل از باز شدن بازارهای هفتگی) + امکان اجرای دستی از تب Actions.

### کش

اگر منبعی شکست بخورد، آخرین مقدار موفق از `data_cache.json` با برچسب تاریخش استفاده می‌شود. ورک‌فلو در پایان هر اجرا فقط در صورت تغییرِ فایل کامیت می‌زند (`chore: update cached macro data [skip ci]`) تا کش بین اجراها دوام بیاورد و حلقه اجرا ایجاد نشود.

## سلب مسئولیت

خروجی این پروژه صرفاً گزارش وضعیت داده‌های کلان و تفسیر خودکار است — توصیه مالی یا سیگنال معاملاتی نیست. بخش Gemini هم صراحتاً در متن خودش این را یادآوری می‌کند.
